# Критерии авторевью PR

Критерии, по которым агент (`pr-auto-review.yml`) ревьюит каждый
pull request. Ревью информативное: вердикт — COMMENT или REQUEST_CHANGES,
блокировки мержа нет. Финальное решение всегда за мейнтейнером.

## 1. Spec — соответствие задаче

- [ ] PR реализует конкретный тикет: в теле есть `Closes #NN` (или
      `Fixes #NN`), diff соответствует AC из issue.
- [ ] Нет скоуп-крипа: изменения вне задачи тикета вынесены в отдельные
      PR. Diff минимален для достижения цели.
- [ ] Коммит реализации ссылается на тикет (`feat: … (#NN)` в subject),
      если тикет есть; chore/docs без тикета — допустимо (AGENTS.md rule #8).

## 2. Standards — правила репозитория

- [ ] Импорты в `src/` — с суффиксом `.js` (`import x from "./foo.js"`),
      `NodeNext` + ESM (AGENTS.md rule #5).
- [ ] В production-коде вне `web/src/api/sdk.ts` нет ручных API-типов,
      endpoint URL, `fetch`/`JSON.stringify` и HTTP-helpers
      (AGENTS.md rules #10–11).
- [ ] Generated-артефакты (`openapi.yaml`, `web/src/api/sdk.ts`,
      `CHANGELOG.md`, `package.json#version`) не правятся руками:
      правится источник (`spec/*.tsp`, Conventional Commits)
      (AGENTS.md rules #9).
- [ ] `.github/workflows/hexlet-check.yml` не изменён.
- [ ] Формат коммитов — Conventional Commits (`type(scope): subject`).

## 3. Quality — качество изменений

- [ ] Новая логика покрыта тестами (unit/e2e — по уровню изменения);
      ручная проверка `make check` зелёная.
- [ ] Нет «мертвого» кода: закомментированные блоки, отладочные
      `console.log`, закомментированные тесты.
- [ ] Следование стилю соседнего кода: именование, структура модулей,
      отсутствие over-engineering (KISS).
- [ ] Обновлена документация, если меняется поведение, команды или
      структура (README, AGENTS.md, `docs/`).

## 4. Risk — риски и безопасность

- [ ] В diff нет секретов, токенов, credentials (gitleaks-чувствительные
      строки). `.env`-файлы и локальные ключи не коммитятся.
- [ ] Изменения конфигов деплоя (`.railway/`, `Dockerfile`, воркфлоу)
      имеют описанный способ отката.
- [ ] Контракт API не сломан без necessity: поля/коды ответов из
      `openapi.yaml` сохраняются либо миграция описана в PR.
- [ ] Изменения env-контракта (`.env.example`) согласованы с
      production-конфигом.

## Вердикт ревью

- **REQUEST_CHANGES** — нарушение секций 1–2 (spec/standards) или
  находка уровня «сломает прод» в секции 4.
- **COMMENT** — замечания по качеству (секция 3), некритичные риски,
  вопросы без явного нарушения.
- Молчание по пункту = пункт прошёл. Каждое нарушение — ссылка на файл
  и строку diff.
