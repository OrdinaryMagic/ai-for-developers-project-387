## Non-obvious drift

### Tool choice fallback: `openapi-typescript@7.13.0` вместо `@hey-api/openapi-ts`

Cart #26 Notes рекомендовал `@hey-api/openapi-ts` (типы + runtime `openapi-fetch` клиент в одном); ticket #29 acceptance явно разрешал fallback. C1-impl выбрал `openapi-typescript@7.13.0`:

- `@hey-api/openapi-ts` пишет несколько файлов (`sdk.gen.ts`, `types.gen.ts`, `index.ts`, плюс `core/`); `#29` acceptance явно просил **single** `web/src/api/sdk.ts`.
- `openapi-typescript` генерирует types-only один файл.

**Side-effect:** Wave-B реализации (#30–#33) писали hand-rolled `fetch()` wrappers (4 файла) — потому что types-only generator не даёт runtime-клиента. Это формально нарушает rule #11 в её первоначальной формулировке ("ручные fetch-обёртки запрещены"). Code-review R1 это признал и обновил rule #11 чтобы быть consistent c инструментом. **Lesson:** выбор tool на #29 имел последствия для всей Wave-B и правил.

### Vitest + TS 7.x: `baseUrl` is gone

A1 emitted `web/tsconfig.json` с `"baseUrl": "."`. Root package.json пинит `typescript@^7.0.2`. TS 7.x **удалил** `baseUrl` option (TS5102). tsc на web/ падал.

Fix при cherry-pick integration: вырезал `baseUrl` (paths `@/*` теперь относительно директории tsconfig.json).

### `/api` prefix в Vite proxy не strip'ался `web/vite.config.ts`

`server.proxy['/api']` A1 определил с `target` и `changeOrigin`, но **без `rewrite`**. То есть Vite форвардил **полный** путь через прокси → backend Fastify получал `/api/meeting-types` — route, который не зарегистрирован. 404 на каждом fetch.

Проявилось **только** в CI e2e (run `41731072901`), не в vitest component-тестах потому что они глобально мокали `globalThis.fetch` через `vi.spyOn`.

Три CI-прохода потребовалось для root-cause:

1. **1st CI run** (после первой волны fixes): `POST /api/meeting-types` (seed) → **404**. Initial fix: убрать `/api` prefix в seed POST.
2. **2nd CI run** (после prefix-fix): Backend возвращает **200 OK**, но spec ожидал **201 Created**. Реальный HTTP code для `POST /meeting-types` в `openapi.yaml` явно задокументирован как **200**: «Реальный HTTP-код — 200; доменная информация об успехе в теле».
3. **3rd CI run** (после status-fix): `GET /api/meeting-types` (browser-side через Vite proxy) → **404**. **Корневая причина**: vite proxy без `pathRewrite`.

Fix в commit `8d86e7f`: добавлен `rewrite: (path) => path.replace(/^\/api/, "")`. После этого run `41738256599` — оба spec'a зелёные.

**Lesson, важная для будущих agents:** vitest component-тесты с `vi.spyOn(globalThis, 'fetch')` мокают network layer и не проверяют, что fetch paths корректно резолвятся через Vite proxy. Единственный способ поймать эту категорию багов — прогонять настоящий e2e (или хотя бы ручной smoke через dev-Vite + dev-backend).

### Hand-written fetch helpers в `web/src/features/**/`api.ts`

4 inline реализации с разными error semantics:

- `web/src/features/guest/api.ts` — inline `res.ok`/`json()`, без специфики для 409/422.
- `web/src/features/guest/book/api.ts::parseJson` — silently `null` на empty body.
- `web/src/features/owner/bookings/api.ts::fetchJson` — throw на `!ok`.
- `web/src/features/owner/event-types/api.ts::parseJson` — throw на invalid JSON, `null` на empty.

Baseline-smell по reviewer (Duplicated Code). Не унифицировано в PR #38 во избежание изменения поведения. **Open follow-up:** `web/src/api/http.ts` — одна каноническая `request<T>` wrapper, чтобы устранить 4-way duplication и снизить drift risk.

## Open follow-ups

- **Fetch helper consolidation в `web/src/api/http.ts`** — refactor на одну каноническую `request<T>(method, url, body)` с discriminated union возвратом (`{ kind: "ok", value: T } | { kind: "domain", error: DomainError } | { kind: "network", message: string }`). Устранение 4-way duplication.
- **UI extensions** (фильтры, cancel/reschedule, past bookings, edit MeetingType) — out of scope cart #26, отдельные тикеты если business требует.
- **Deploy pipeline** (Fly.io / Vercel / Docker publish) — out of scope, отдельная карта.
- **CI cache invalidation для Playwright browsers** — `key: playwright-browsers-${{ runner.os }}-${{ hashFiles('package-lock.json', 'web/package-lock.json') }}`. Если browser versions меняются в `@playwright/test`, cache поможет только пока package-lock.json меняется. Альтернатива — hash на пакет `@playwright/test` напрямую.
- **Tailored OpenAPI preview** — после PR #38 OpenAPI spec файл не правился; тем не менее vite proxy pathRewrite показал что между /api-prefix клиента и backend без-prefix требуется согласование. В будущих картах (например, добавление API аутентификации) может быть полезно ввести `X-Forwarded-Prefix` или аналогичный header чтобы клиент мог бы знать заранее.
